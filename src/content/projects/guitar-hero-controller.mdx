## 01 / Problem

A Guitar Hero controller is fun hardware, but games expect a keyboard or a
joystick. Making a physical device behave like a standard Linux input device
requires two layers: firmware that reads the hardware cleanly, and a driver
that turns serial bytes into kernel input events.

## 02 / Architecture

```text
Arduino (5 fret buttons + joystick)
   │  4-byte binary frame @ 115200 baud
   ▼
C++ driver (termios, 8N1, raw)
   │  /dev/uinput
   ▼
Linux virtual input device (keyboard/joystick)
```

## 03 / Implementation

- **Firmware** (`v1_binario.ino`): 5 fret buttons on pins 2–6 with
  `INPUT_PULLUP`; joystick VRx/VRy/SW on A0/A1/D7. State is packed into a
  4-byte frame `[0xAA] [buttons] [X] [Y]` sent every cycle at 115200 baud.
- **Driver** (`src/main.cpp`): opens the serial port (`B115200`, 8N1, raw, no
  echo/canonical via termios/fcntl), creates a virtual input device with
  `uinput`, and translates each frame into keyboard/joystick events.
- **Build**: `make` compiles to `build/driver`; `make run` opens the port and
  creates the device. Port is configurable (e.g. `/dev/ttyUSB0`).

## 04 / Engineering Decisions

- **Debounce without `delay()`** — `millis()`-based debounce keeps the loop
  responsive instead of blocking the firmware.
- **Binary protocol over ASCII** — fixed 4-byte frames are simpler, faster and
  deterministic vs. parsing text over serial.
- **uinput over evdev hacks** — the kernel's virtual input API is the correct
  interface for synthesizing input on Linux.

## 05 / Testing

The repo ships a Makefile for build/run and technical documentation of the
protocol and driver. Peripheral setup (serial permissions, `input` group,
`/dev/uinput`) is documented.

## 06 / Results

Real hardware — an Arduino with a joystick — usable as a keyboard/joystick on
Linux, end to end. This is the low-level systems layer most students never
touch: serial, termios, kernel input, C++.

## 07 / Lessons Learned

- Level-crossing is a strength: firmware in C++ on a microcontroller and a
  kernel-level driver in C++ on the desktop share one design.
- A precise, documented wire protocol makes the two halves independently
  testable and debuggable.
- `INPUT_PULLUP` + `millis()` debounce is the baseline for reliable button
  input on Arduino.
